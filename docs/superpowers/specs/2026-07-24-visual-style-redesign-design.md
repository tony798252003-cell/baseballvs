# 整體視覺風格改版 設計規格

**日期：** 2026-07-24
**功能：** 統一全 App 視覺語言（色彩、字重、圓角、陰影規則），並針對比賽記分主畫面（GameScreen）右側資訊區做排版與資訊層級重整。

---

## 背景與目標

這是「大改版」規劃中的第三個子專案（另兩個子專案——後台音樂設定流程已完成、比賽記分主流程規則本身——各自獨立處理）。

目前問題（使用者確認）：
- **畫面之間風格不一致**：MenuScreen / LineupSelectionScreen 是亮色系（白＋天藍/靛藍漸層），GameScreen 是暗色球場風（深藍灰＋黃色），AdminScreen 又是另一套暗色系（slate 灰＋黃色）。
- **整體「很AI很飽和」**：大量彩色漸層、圓角、陰影堆疊，色票之間飽和度/明度不一致（例如原本三個遊戲模式各用一個最大飽和度的純色，互相搶戲）。
- **資訊雜亂**：尤其 GameScreen 右半邊（打者資訊、操作按鈕）——按鈕散落四處（floating absolute 定位、顏色各異）、多重漸層背景、資訊密度過高沒有主次。

使用族群包含小孩，需要活潑但不刺眼、不雜亂的視覺語言。

### 目標

- 建立一套跨畫面共用的色彩／字重／圓角／間距規則，取代目前三套各自為政的視覺語言。
- 保留 GameScreen 左側球場照片背景與沉浸感（使用者明確要求保留），僅重新設計右側資訊區的排版與配色。
- 三個遊戲模式（單人/對戰/進階）維持各自代表色的活潑感，但飽和度/明度統一，不再互相搶戲。
- 拿掉右側資訊區的浮動按鈕、多重漸層背景；統一資訊層級與按鈕分組邏輯。
- 先發打序清單比照真實 CPBL 轉播打序圖的排版質感（編號徽章＋守位色塊＋姓名對齊），並為球員姓名長度（2～7 字以上，含原住民族名間隔點）訂出明確的顯示規則。

---

## 範圍

### 1. 全域色彩系統（C2：清爽粉彩）

跨畫面共用的基礎色票：

| 用途 | 色票 |
|---|---|
| 背景（亮色畫面） | 白 `#ffffff` / 極淺灰 `#f9fafb` |
| 主要文字 | 深灰 `#1f2937` |
| 次要文字 / 說明 | `#6b7280`、`#9ca3af` |
| 邊框 / 分隔線 | `#e5e7eb`、`#f3f4f6` |
| 藍（單人模式／正面動作／資訊類） | 主色 `#6d9dc5`，淺底 `#eef4f9`，深字 `#3f6a8c` |
| 橘（對戰模式／強調／目前選取） | 主色 `#e0a458` |
| 綠（進階模式／輔助正面動作） | 主色 `#7fb08a` |
| 磚橘紅（負面/出局類動作） | 主色 `#c0785a`／`#c0524a`（出局圓點用） |
| 深底（記分板／頂部列） | `#1f2937` |

**設計規則：**
- 不使用多層漸層背景；色塊一律純色（`background: <hex>`），必要時用邊框/底色深淺分層取代漸層堆疊。
- 三個遊戲模式色（藍/橘/綠）飽和度與明度需落在同一區間，靠色相區分而非靠飽和度搶戲。
- 圓角統一：卡片/按鈕 `rounded-lg`（約 6-8px），小徽章 `rounded` (約 3-4px)。
- 陰影降到最低：資訊卡片以邊框(`border`)+底色深淺分層為主，不疊加多層 `shadow`。
- Emoji 僅保留在少數強調性場合（如 ⚾ App 標題、🔥 投手代表符號、🎵 播放按鈕），不作為系統性圖示語言；其餘互動元素沿用專案既有的 `Icons.vue` SVG 圖示集。

此色彩系統套用到 MenuScreen、LineupSelectionScreen、AdminScreen 既有的亮色底畫面，取代目前的靛藍/天藍漸層。GameScreen 左側球場照片區維持不變（見第 3 節）。

### 2. AdminScreen / MenuScreen / LineupSelectionScreen 套用方式

- 三個遊戲模式按鈕（單人/對戰/進階）改用統一飽和度的藍/橘/綠三色（同第 1 節色票），拿掉現有漸層與多重陰影。
- AdminScreen 由目前的深色 slate 主題改為與 Menu/Lineup 一致的亮色系，tab 列、表格、按鈕比照第 1 節色票與圓角規則。
- 這兩個畫面本次不涉及排版結構調整，只調色彩／圓角／陰影規則，維持既有版面配置。

### 3. GameScreen 排版與資訊層級重整

**左側球場區：維持不變。** 球場照片背景、頂部標題列、局數/出局的記分板覆蓋層、壘包顯示（`BasesDisplay`）都保留現有結構——這是使用者明確要保留的沉浸感。頂部覆蓋列因為疊在照片上，維持半透明深色底（`rgba(31,41,55,0.85)`）搭配橘色強調邊框，以確保在照片背景上仍清晰可讀，不套用亮色底（亮色底疊在照片上會糊掉，因此此處是唯一例外）。

**右側資訊區：整體重新排版。** 由上到下：

1. **9 局逐局記分板**：沿用現有 `ScoreBoard` 元件的完整資料（9 局＋R欄），底色改為 `#1f2937` 深底＋白字，R 欄用橘色 `#e0a458` 標示，取代原本的綠色漸層條。
2. **打者／投手並排格**（不再用「vs」文字連接，而是左右兩個獨立格子，中間一條分隔線）：
   - 每格內大頭照在左、其他資訊在右（不是大頭照置中在上、文字在下）。
   - 大頭照比例固定 **7:9**（寬:高），四周留間距、帶圓角，不貼滿格子邊緣、不撐滿格高。
   - 打者格：大頭照＋「打者」標籤／背號姓名＋B/S 球數徽章＋代打／🎵播放 小按鈕（原本浮動在畫面四角的按鈕，收進這裡）。
   - 投手格：大頭照＋「投手」標籤／姓名背號＋換投小按鈕。**不顯示**被安打/三振/四壞/ERA 等數據，只需清楚呈現「現在投手是誰」。
   - 局數／出局**不**在右側重複顯示（左側球場區已經有）。
3. **操作按鈕區**：4×3 grid（12 格）。目前 8 個既有按鈕（安打／保送／觸身／觸擊／高飛犧牲打／出局／三振／重置球數）依「正面動作＝藍/綠、負面動作＝磚橘紅、中性動作＝灰」分組上色；多出的第 3 列以一個橫跨全寬的「＋更多情境按鈕（下階段規劃）」預留區塊呈現，**實際新按鈕要接的計分規則屬於「比賽記分主流程」子專案範圍，本次僅確保排版留得出空間**。
4. **先發打序**（見第 4 節）：獨立直式欄位，鎖在資訊區最右側，撐滿整個資訊區高度（9 棒平均分配，不因棒次少而在下方留白）。

### 4. 先發打序清單樣式

參考真實 CPBL 轉播打序圖的排版質感，但套用本專案的亮色配色（不用深藍底）：

- 每列由左到右：**編號徽章**（14×14px 方形、帶邊框、圓角、藍色邊框＋藍字）→ **姓名**（固定寬度欄位，見下方命名規則）→ **守位縮寫色塊**（貼合文字寬度、不撐滿剩餘空間，`margin-left:auto` 推到最右）。
- 當前打者整列反白標亮：底色橘 `#e0a458`，編號徽章與守位色塊改為白底深字（對比色）。
- 守位色塊只有在該球員有守位資料時才顯示（主要是**進階模式**才會記錄守位；一般模式打線目前沒有指定守位）。其他模式沒有守位資料時，該色塊不顯示，姓名列正常靠左走版即可，不留空白色塊佔位。

**姓名長度顯示規則**（固定寬度欄位 38px，字級以此欄寬為基準）：

| 條件 | 呈現方式 |
|---|---|
| 含間隔點（`．`／`·`／`‧`，常見於原住民族名，如「吉力吉撈．鞏冠」）且**總長度 > 6 字** | 只顯示點前面的族名部分，字級維持正常 11px；`title` 屬性放完整全名（含點後登記名），滑鼠 hover／觸控長按顯示 |
| 2～3 字（含上述含點但總長 ≤ 6 字的情況） | 字級 11px，欄位用兩端對齊（CSS `text-align: justify; text-align-last: justify`）撐開字距，使短名字與長名字視覺寬度一致 |
| 4 字 | 字級 9.5px，兩端對齊 |
| 5 字 | 字級 8.5px，字距微調（`letter-spacing` 略收） |
| 6 字（無間隔點，或有點但仍 ≤ 6 字判斷之外的情況） | 字級 7.5px，字距進一步收緊 |
| 7 字以上（無間隔點特殊規則可套用） | 固定字級（9px），超出以 `text-overflow: ellipsis` 省略，`title` 放完整全名 |

判斷優先順序：**先檢查「含間隔點且總長 > 6 字」規則 → 若不符合，才依字數落入對應的字級級距。** 所有列一律套用 `white-space: nowrap`（不換行）；5 字以內在此欄寬、字級規則下必定完整顯示不截斷，6 字以上則依上表縮小字級或截斷處理，但同樣不換行到第二行。

## 不在範圍內

- 比賽記分主流程本身的規則設計（觸擊、高飛犧牲打等新按鈕實際要如何計算打點、推進跑者、記錄成績）——這是獨立子專案，本次只確保 GameScreen 排版留得出對應的按鈕格位。
- ChantPlayerScreen 的視覺調整（未在本輪討論範圍內，維持現狀；如需一併套用色彩系統可於後續追加）。
- GameScreen 左側球場照片區的排版或視覺調整——明確保留不動。
- 字型（font-family）本身不更換，沿用專案既有的無襯線字型與現有粗細（`font-bold` / `font-black`）搭配規則；本次改版只調色彩、圓角、陰影、排版結構，不換字型家族。
- 一般模式／對戰模式打線的守位資料回填（守位色塊在沒有資料的模式下就是不顯示，不代表本次要去補資料）。

## 驗證方式

- MenuScreen / LineupSelectionScreen / AdminScreen：套色後手動比對三個畫面的背景色、文字色、按鈕圓角/陰影是否一致，不再有漸層堆疊。
- GameScreen 右側資訊區：對照本文件第 3、4 節逐項核對——局數/出局不重複顯示、打者投手左右並排且大頭照 7:9 比例留邊距、按鈕 4×3 分色分組、先發打序撐滿高度且姓名對齊規則符合上表。
- 姓名顯示規則：至少用 2 字、3 字、4 字、5 字、6 字、7 字以上、以及一個含間隔點的原住民族名（如「吉力吉撈．鞏冠」）分別建立測試球員資料，確認每種長度都套用到正確字級／截斷規則，且 5 字以內實際不換行。
